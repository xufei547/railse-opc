# 网页：手机上的收件箱（PWA）

## 是什么

手机优先的收件箱网页，代码在 `web/`（Vite + React + TypeScript），构建产物嵌进 `railse` 二进制，由 hub 同源托管：打开 `https://<hub 域名>/` 就是它，不用另外部署，也不用配置 hub 地址。在 iPhone 上加到主屏幕后是一个 PWA（独立窗口、有图标），能收 Web Push 通知。网页能做的事与 hub 的接口一一对应（见 [hub.md](hub.md) 的 API 表），它没有任何 hub 之外的能力。

## 构建与部署

- `make web`：`cd web && npm ci && npm run build`，Vite 产物写进 `internal/hub/webui/dist/`（`go:embed` 把它嵌进二进制）。产物不入库，目录里只有 `.gitkeep`；构建后 `.gitkeep` 会补回，工作树不脏。
- `make build`：先 `make web` 再 `go build -o railse ./cmd/railse`。直接 `go build` 也能编，但没有网页：hub 的网页路径回 503“网页未构建：在仓库里运行 make web 后重新构建 railse”，接口照常可用。
- hub 不需要为网页做任何配置。HTML 带 CSP（脚本、样式、图片、连接只许同源，不许内联脚本、内联样式与 eval）与 `X-Frame-Options: DENY`；`assets/` 下带哈希的文件长期缓存，其余（`index.html`、`sw.js`、清单、图标）`no-cache`，升级 hub 后下次打开即是新版。
- **要推送，必须** `railse hub run --public-url https://<hub 域名>`：只收 https 源（不带路径），localhost 也要 https；不设时推送停用，设置页会说明原因。**域名从第一天起固定**：推送订阅与主屏幕应用都绑在源上，换域名等于每台手机删掉图标、重新添加、重新开启通知。公网部署见 hub.md 的“部署与反向代理”（反向代理须保留原 Host，否则同源校验让写操作全部 403）。
- **登录 cookie 的 Secure**：hub 在 TLS 反向代理后面时自己看不到 TLS，设了 https 的 `--public-url` 时 cookie 自动加 Secure，没设时要加 `--secure-cookies`；在反向代理后面再加 `--trusted-proxy <代理地址>`，否则按 IP 的登录限速对所有人算成一个来源。完整命令例如 `railse hub run --listen 127.0.0.1:8787 --public-url https://hub.example.com --trusted-proxy 127.0.0.1`。

## 第一次使用（iPhone，iOS 16.4 起）

1. Safari 打开 `https://<hub 域名>/`，用 `railse hub password` 设的密码登录。
2. 分享 → 添加到主屏幕 → 添加；回到主屏幕，**从图标打开**（Safari 标签页里没有推送能力：收件箱顶部有引导，设置页只显示这三步，不显示“开启通知”）。
3. 设置 → 开启通知 → 系统授权框里选允许。
4. 点“发一条测试通知”，几秒内应弹出“Railse / 通知正常”。

真机上“完全关闭、锁屏、数小时后”能否收到，以 [iOS 实验文档第 8 节](superpowers/specs/2026-10-21-ios-webpush-findings.md) 的联调记录为准。

## 页面

- **收件箱**：“等你回答”是 agent 在终端里提的问题（只展示，要去终端回答；对方继续之后自动消失）；“待处理”（审批和提问）按项目分组，每张卡片第一行是要做什么（如“把代码推到远程仓库（origin 的 main）”）与风险等级、相对时间，第二行命令、路径或问题，第三行 CLI · 机器 · 项目；含被隐藏部分的有红标。提问卡片第一行是“在问你：<第一题>”（超过 60 字截断）加灰色标签“提问”，第二行是第一题的选项用“ / ”连起来（如 `Apple / Banana`），第三行 CLI · 机器 · 项目。底部导航的数字是待处理条数加等你回答条数。顶部横幅：实时连接断开（正在重连，可点刷新）、加载失败、自动审批已暂停、通知已失效（去设置重新开启）、iPhone 上还没加到主屏幕。
- **请求详情**（`/r/<id>`，通知点开直达这里）：最上面一张说明卡：谁想做什么（如“Claude Code 想访问网址 api.example.com”）、在哪个项目和机器、为什么要你决定（按风险说，自动审批暂停时先说暂停；命令的目录不是项目根时，在哪一句末尾带上目录；“为什么”与下面三行只在还等你决定时显示，处理过的请求没有）；下面是原样的命令、路径或网址，再下面三行说批准、拒绝、记住会怎样（“记住”一行按能不能记成放行说：对外、不可逆、未知、项目外或没有项目根的操作只能存成拒绝规则，其余可以存成规则；question 是“去那台机器的终端回答”，webhook 是“会回调给发起它的工作流”）；处理过的请求在命令下面一行显示状态标签、一句人话的结果（如“你批准了”“规则 builtin-read 自动批准了”“agent 那边先结束了，不用你处理”“等太久过期了，agent 已交回终端”）、决定时间与送达。机器、项目、工具、风险、引擎理由、时间与审计收在默认折叠的“详情”里。`has_redacted` 的请求顶部醒目告警（在说明卡之前）：屏上的不是原文，凭据被换成了 `<redacted>`，定级却是按原文做的。
- **答题页**（提问的详情页，顶栏是“提问”，没有风险标签，也没有批准、拒绝与“记住”）：说明卡“Claude Code 在问你”加项目与机器，下面三行提示：选一个答案 agent 立刻继续；也可以自己填一句；“让它在终端问我”会把问题交回终端。每道题一块：小标题（Claude 给的 `header`）、多选题标“可多选”、题面、选项（单选是圆点，多选是方框，选项下面有它的说明）、“自己填”输入框（至多 1000 字）。单选点一个选项；多选可勾几个，答案按选项顺序用“, ”连接；自己填的一句原样交给 Claude。填了“自己填”会清掉这道题已选的选项，再点选项会清空自己填。底部操作条（“还有 N 题没答”提示、主按钮“回答”和次要按钮“让它在终端问我”）固定在底部导航上方；每道题都有答案，“回答”才可点，每题都有答案后，按钮文字带上答案（如“回答：Banana”；多选用“、”连接，自己填的超过 20 个字符截断，多道题用“；”连起来；英文界面为 `Answer: Banana`，连接符分别是 `, ` 与 `; `），提交中显示“正在提交…”，不会自动提交；“让它在终端问我”点了 agent 不再等手机，终端里照常弹出原生选项。答完后页面变成每题一行“问题 → 你的答案”，状态行“已回答 · 你答了”并显示答案是否已送达 agent；交回终端的只列问题，状态行“交回终端 · 交回终端问了”。答题只对 Claude Code 的选择题有效，题目里认得出的凭据在本机已换成 `<redacted>`（有这种内容时顶部同样醒目告警）。请求在别处先结束时（终端里已经答了、等太久过期、机器被吊销）页面换成结果视图，状态行用同一套人话（如“等太久过期了，agent 已交回终端”“agent 那边先结束了，不用你处理”），提交时撞上这种情况会弹红色“没有生效”；答案不合规（400）或连不上 hub 只在表单里红字提示，改了可以再试。
- **批准、拒绝**：底部弹出面板，可写备注。备注只进审计，不给 agent 看（webhook 的备注随回调发给来源系统）。
- **记住**：打开“记住”后先向 hub 要草案（`propose`，只算不存），显示“将放行（或拒绝）命令 <锚点>（仅项目 X / 所有项目）”与规则原文；范围可在“项目”与“全局”之间切换（没有项目根时只能全局）。确认后才入库并下发给所有机器。记不住时开关不可选或给出 hub 的说明：webhook 请求、含被隐藏部分的请求；对外、不可逆、项目外改动与无法判断的操作不能记成放行；命令或路径超过 4 KiB；没有项目根的命令与文件写入不能记成放行（定级依赖项目根）。
- **结果提示**：决定之后固定在底部导航上方：绿色“已生效”（已批准或已拒绝、是否已送达 agent、学到的规则 id），红色“没有生效”（这条在别处有了结果，括号里是与状态行同一句人话，如“agent 那边先结束了，不用你处理”“这台机器已被吊销”）。提问的提示是“已回答，答案正在送回 agent”（送达后“已回答，已送达 agent”）与“已交回终端，agent 会在终端里问你”；回答时撞上 409，只有这条最终是“已回答”而且答案与你提交的完全一致才算“你的决定已生效”，别的设备答了不同内容就是红色“没有生效”。答案没能送到时状态行说“答案未送达：agent 已不再等这条（多半已在终端问了你）”。
- **历史**：按状态筛选（全部、已批准、已拒绝、已回答、自动放行、自动拒绝、交回终端、已过期、已取消、问题与完成），每条带一句人话的结果，与审批页的状态行同一套文案：“你批准了”“你答了”“你批准并记住了（规则 <id>）”“规则 <id> 自动拒绝了”“交回终端处理了”“等太久过期了，agent 已交回终端”等；原始的来源（`decided_by`）与备注只在详情的“依据”“备注”里。先列最近 100 条，可加载到 500 条。
- **规则**：每条的来源（内置、手写、学来的）、命中次数、来自哪条请求、规则原文；可启停、删除（内置的只能停用）、导入（整套替换，至多 1 MiB，先确认）、导出（`railse-rules.yaml`）。红标“可放行高风险操作”（`elevated`）是能自动放行对外或不可逆操作的规则，只能来自导入的手写规则，启用前要再确认一次。网页不编辑规则：改规则就导出、改 YAML、再导入。
- **机器**：在线状态、版本、最近在线与接入时间；吊销（先确认）后它的密钥立即失效、在等的请求被取消，重新接入要 `railse hub token` 加 `railse agent enroll --force`。
- **设置**：暂停自动审批（hub 的总开关：审批请求交回终端，手写的拒绝规则照常生效；Claude Code 的选择题不受暂停影响，照样送到这里，开关说明、确认框、暂停后的提示与收件箱横幅都这么写；立即下发到所有机器；机器上 `railse agent pause` 设的本机暂停不受这里影响，这里恢复也解除不了它，本机暂停也不会同步到 hub）、语言（“语言 / Language”：跟随系统、中文、English，英文界面里标题只写 Language；选择存在本机浏览器的 `railse.lang`，选“跟随系统”就不存；切换时若通知已开启，先用新语言重新登记这台设备的推送订阅（失败不挡切换），然后重载页面）、通知（开启、关闭、发测试通知）、hub 状态（规则版本、在线机器、待处理（审批加提问）、已运行），退出登录。退出登录先关闭这台设备的通知（hub 删掉它的订阅、浏览器退掉订阅；最多等 3 秒，关不掉也照常退出），再删登录会话：推送订阅与登录是分开的，只退出登录的话锁屏上照样会收到审批摘要。再登录后要重新开启通知。

## 通知

- **什么时候推**：新的待审批（permission）、新的提问（ask）、webhook 请求和新的 question；`done` 不推；守护进程重连后补发的、早于此刻 2 分钟以上的旧 question 进收件箱但不推。同一条请求用请求 id 作 tag，通知中心只留一条。
- **长什么样**：审批的标题是谁要做什么，例如“Claude Code 要联网 · blog”（Claude Code、Codex 或 Gemini CLI，认不出时写 Agent；动词按风险：联网、往外发、做不可逆的操作、改项目外的文件、跑一个没见过的命令、改项目里的文件、读文件），后面跟项目名，接了不止一台（名字不同的）机器时再跟机器名（去掉 `.local`）；正文第一行是命令、路径、网址或 MCP 的“服务/工具”（认不出的工具写工具名），第二行“点开批准或拒绝”。提问的标题是“Claude Code 在问你 · 项目 · 机器”（机器名同审批的规则：接了不止一台时才带），正文第一行是第一道题的题面，多于一题时后面跟“ 等 N 题”，第二行“点开回答”；question 的标题是“Claude Code 在终端等你回答 · 项目”，正文是问题（要去终端回答）；webhook 的标题是“工作流等你批准”，正文是来源给的标题。
- **点开直达**：Service Worker 对每条推送都弹通知（iOS 对不弹通知的推送会吊销订阅），点通知时让已打开的窗口跳到 `/r/<id>`，跳不了就开新窗口；只认本站路径。
- **已处理的自动收掉**：网页每次拿到收件箱状态（打开时的加载、实时连接推来的变化、你批准或拒绝之后）都会关掉通知中心里已经不在待处理（审批和提问）、等你回答里的通知（含测试通知），同一秒内至多收一次；点通知本身也会先收掉被点的那条再打开详情。iOS 不允许静默推送（不弹通知的推送会让订阅被吊销），hub 没法在请求处理完时远程收掉通知：在终端或别的设备上处理掉的请求，它的通知要等你下次打开网页才消失。
- **前台也会响**：页面开着时实时通道已经把新请求推到收件箱，iOS 仍会弹横幅，这是 iOS 的规定，压不掉。
- **通知失效**：推送服务对订阅回 404 或 410 时 hub 立即删掉它；其余失败要连续至少 5 次、且这一轮第一次失败已过去 24 小时才删（短暂故障不删好订阅）。删掉之后网页顶部出现“通知已失效”横幅，到设置里“重新开启通知”即可。订阅被浏览器更换时 Service Worker 自动重新登记（登录过期时登记不上，下次打开网页会看到横幅）。
- **换钥、换密码**：`railse hub vapid --rotate` 与 `railse hub password` 都删除全部订阅，每台手机都要（重新登录后）在设置里重新开启通知。
- **设备丢了**：在服务器上先 `railse hub password` 换密码（同时删掉全部登录会话与推送订阅，丢掉的设备立即登不进、收不到推送），再 `railse hub vapid --rotate` 换推送密钥；之后每台还在用的手机用新密码登录、重新开启通知。详见 hub.md“安全要点”的“退出登录与设备丢失”。

## 开发

- `cd web && npm ci && npm run dev`：Vite 开发服务器（默认 `http://localhost:5173`），把 `/api`、`/ws` 代理到 `RAILSE_HUB`（默认 `http://127.0.0.1:8787`，例如 `RAILSE_HUB=http://127.0.0.1:9000 npm run dev`）。hub 的写接口与 `/ws/client` 校验 Origin 与 Host 同源，代理把 `Origin` 改写成 hub 的源才能通过——**这只用于本机开发**，部署时网页始终由 hub 同源提供，不能从别的源调 hub。开发服务器不带 hub 的 CSP，与 CSP 有关的改动要用 `make build` 后的 hub 或 `make e2e` 验证。
- `npm run check`：`tsc --noEmit` 与 Vitest（纯逻辑模块：接口层、实时通道、状态、格式化、决定面板、推送状态、Service Worker 等）。`make test` 同时跑 Go 侧的 gofmt（查入库的与新建还没 git add 的 Go 文件，不查 .gitignore 里的）、vet 与 `go test -race`。依赖只用 `package.json` 里列出的包，`package-lock.json` 入库，安装一律 `npm ci`。
- `make e2e`（即 `scripts/e2e-web.sh`）：`npm ci`、构建网页、把二进制编到临时目录，Playwright（Chromium，手机尺寸；两个项目：`chromium` 跑下列用例、浏览器语言 zh-CN，`en` 的 `locale` 为 en-US，跑 `web/e2e/en.spec.ts`）起真实的 hub（临时目录、随机端口）与接入它的守护进程，用录制的 Claude `PermissionRequest` 样本直接运行 `railse hook claude --socket <临时 socket>` 模拟审批：登录 → 收件箱为空 → `curl https://api.example.com/v1/x` 出现 → 详情 → 批准并记住（看草案）→ 钩子输出 `"behavior":"allow"` → 规则页多一条学来的规则；再来 `git push origin main` → 带备注拒绝 → 钩子输出 `"behavior":"deny"`（不含备注）→ 历史里“已拒绝、你拒绝了”。另有答题的用例：录制的 `PreToolUse` 样本（`internal/adapter/testdata/claude/2.1.280/PreToolUse.json`）录的是一次 Bash 调用，用例换掉它的会话 id、`prompt_id`、`cwd`、`transcript_path`、`tool_name`（改成 `AskUserQuestion`）、`tool_use_id` 与 `tool_input`（换成计划里 2026-10-31 在 Claude Code 2.1.280 真机抓到的那段 `AskUserQuestion` 输入，原文拼进 stdin）再运行钩子：收件箱出现“在问你”→ 选 Banana 回答 → 钩子输出 `permissionDecision: allow`、`updatedInput` 里 `questions` 与输入逐字节相同、`answers` 是所选；点“让它在终端问我”→ 钩子无输出；多选加自己填的组合同样核对。每个用例结束时断言页面上没有 CSP 违规与未捕获的异常（另有一条用例故意违规，确认检测本身有效）。所有进程的数据目录与 `HOME` 都在临时目录里，不碰 `~/.railse`、`~/.railse-hub` 与任何 CLI 的配置；退出时（成功、失败或 Ctrl-C）停掉这次起的全部 railse 进程、删掉临时目录，失败时打印 hub 与守护进程日志的末尾，截图与 trace 在 `web/test-results/`。额外参数传给 `playwright test`，如 `scripts/e2e-web.sh --headed`。

## 已知限制

- 端到端是审批主流程（批准并记住、带备注拒绝）、答题三条（用真机录的 `AskUserQuestion` 输入单选作答并核对钩子输出、交回终端、多选加自己填）和一条 CSP 检测自检，另有英文项目一条用例（登录 → 批准 → 答题 → 历史、规则、机器、设置，每个页面都断言没有中日韩文字，历史页不计请求摘要），页面的其余交互靠 Vitest 覆盖的纯逻辑与人工检查。
- 推送在 iOS 上“完全关闭、锁屏、数小时后”三项以真机联调记录为准；收不到时按设计文档第 8 节决定是否加 Bark。
- 规则页不做编辑；暂停只有 hub 总开关，不能按机器单独暂停。
- 不做离线缓存：Service Worker 只管推送与通知点击，没有网络时网页打不开。

## 语言

网页有中文和英文两套界面。语言的解析顺序：设置里存的选择（`railse.lang`，`auto`/`zh`/`en`，auto 不存）→ `navigator.language` 以 `zh` 开头为中文 → 其余都是英文；结果写进 `<html lang>`（`zh-CN` / `en`）。manifest 是固定的英文描述；Service Worker 的兜底通知正文（推送载荷缺失时）按 `navigator.language`，不看这里的手选。推送文案跟订阅走：登记订阅时带 `lang`（见 [hub.md](hub.md)），所以一台手机的网页和锁屏通知语言一致。浏览器自己轮换订阅时 Service Worker 的 `pushsubscriptionchange` 只能带 `navigator.language`，手选的语言此时会退回系统语言，到设置里换成别的语言再切回来即可（通知已开启时才会重新登记）。不翻译：hub API 的错误句子、hub 与守护进程日志、原始 `engine_reason`（网页对认得出的守护进程原因自带英文）；hub 没配 `--public-url` 时，英文设置页显示固定的英文句子。
